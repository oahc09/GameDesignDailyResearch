# 2048（game-000015）

## 核心体验
滑动合并、指数成长。乐趣是"把混沌的随机刷新整理成单调有序的键盘象限"，以及求偶式等待那颗 10% 的 4。

## 规则与状态转移（含最简伪代码）
- 状态：`(4×4 网格, score, won)`；输入：四向滑动（全部块同步位移）。

```text
# 源码核验口径（game_manager.js，MIT）
slide(dir):        按方向反序遍历；findFarthestPosition 滑到阻挡
merge:             相邻同值且本回合未合并 -> 翻倍合并（mergedFrom 标记防连环）
                   score += merged.value          # 合并即得牌面分
spawn:             每次有效移动后 addRandomTile：
                   value = Math.random() < 0.9 ? 2 : 4   # iid，无记忆
                   startTiles = 2                  # 开局两块
终局:              movesAvailable() == false       # 无空格 且 无相邻同值
```

## 输入与输出
- 输入：四向滑动（一次输入驱动全场）。
- 输出：合并动画与分数跳字、最高分持久化、2048 达成后的继续模式。

## 难度与学习曲线
难度上限由求解器界定：ov3y 的 expectiminimax（单调性+平滑度+空格+最大值启发）首个高概率到达 32768；后续 expectimax 实现把 32768 到达率推至 80%+（检索口径，见来源）。人类中等策略（角固定+蛇形）可达 2048/4096——求解器把"深不可测"变成了可量化谱系。

## 关联机制与模式
- 机制：mechanic-000016（iid 无记忆生成）
- 模式：pattern-000011（求解器界定的深度谱）
- 渊源与去重：1024（Veewo Studio）的克隆、概念近似 Threes（Wikipedia 口径；Threes 作者称曾测试并否决合并机制为"太容易"——同一机制的两种设计判断并存，极有价值）。Threes 未建实体（预排周一），EVOLVES_FROM 边缘暂缺，在 未知 中登记。

## 设计权衡
- 优点：MIT 开源是它病毒传播的放大器（一周 400 万访客；社区衍生即"开源之美"——Cirulli 语，Wikipedia）；iid 无记忆随机让每局独立、学习干净；实现 ≤500 行。
- 缺陷：作为克隆缺乏署名链（"a clone of a clone"，The Independent 转述）；iid 旱灾期无保底（与 7-bag 的对照正是本日主题）；Ketchapp 未授权 iOS 克隆再现了超休闲的抄写生态（与 game-000004 同发行商，Wikipedia）。
- 反例：Threes 创作者否决了合并机制（认为太容易）却做出了更耐玩的原作——"机制可行性"与"机制选择"是两个判断。
- 适用场景：需要"整整齐齐"的合并玩法原型；教学级随机化案例。

## 推断与未知
- **未知**：Threes/1024 实体的独立卡与精确发布日期（预排周一）；原版仓库 README 的完整谱系表述（本卡引用 Wikipedia 转述）。
- **推断（分析而非事实）**：90/10 而非 50/50 是"成长速度"旋钮——4 出得太频繁会让指数曲线失控、低牌面失去规划价值；无记忆性则让玩家无法"数块"（与 7-bag 对照）。
- **推断（分析而非事实）**：合并即得牌面分（score += value）使分数近似"总消除量"，为连击/翻倍等现代改写留出了公理化空间。
